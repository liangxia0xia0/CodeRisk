# CodeRisk 认证、权限与安全设计

**项目名称：** CodeRisk——代码变更风险评估与任务难度量化平台  
**文档版本：** V1.2 修订稿  
**文档状态：** 待交叉审查；相关接口与安全代码尚未实现  
**目标：** 在个人账号模式下，保护用户提交的 Diff、报告和对话，限制模型与解析流程的权限，并为本地演示和云端部署提供可执行的安全边界。

## 一、设计原则

1. Go 后端是身份、授权、任务、报告、对话和审计的唯一业务权威。
2. 默认拒绝；所有用户资源访问都必须从已认证用户身份出发校验归属，不能信任请求中的 `user_id`。
3. Diff 是不可信输入；不得执行其中的代码、命令、构建脚本或提示词指令。
4. 外部模型调用前必须明确告知用户 Diff 和必要上下文会发送给模型供应商，并取得确认。
5. 密钥、原始 Diff 和完整对话正文不进入普通应用日志。
6. 首版采用最小可维护的安全措施，不提前实现组织、团队 RBAC、SSO、复杂角色体系或用户自带 API Key。
7. 用户数据、RAG 知识来源和 Agent Memory 均须遵守用户归属与最小权限；不能把检索结果或记忆内容当作已验证事实。

## 二、身份认证

### 2.1 账号范围

- MVP 仅支持个人账号：注册、登录、退出。
- 邮箱仅作为账号标识，不要求首版完成邮件验证、密码找回和第三方登录；这些能力列为后续扩展。
- 注册与登录接口需要速率限制；重复邮箱返回统一、不过度泄露账号存在情况的错误语义。
- 密码不得明文存储或记录日志。使用成熟密码哈希算法及合适成本参数（Go 可采用 bcrypt；成本参数通过配置/部署基线确认），不得自行设计加密算法。
- 密码长度设置明确的最小和最大值；拒绝空密码和超长输入，避免资源消耗攻击。

### 2.2 会话与令牌

MVP 使用短期 JWT Access Token 与 Refresh Token。两者由 Go 后端签发，并通过 HttpOnly Cookie 交给浏览器；前端 JavaScript 不读取或持久化令牌：

- Access Token 默认有效期 15 分钟；Refresh Token 默认有效期 7 天。有效期均由服务端配置控制，属于首版工程默认值，需纳入测试。
- Cookie 设置 `HttpOnly`、`SameSite=Lax`；生产 HTTPS 环境设置 `Secure`。本地开发可按开发配置关闭 `Secure`，不得用于生产。
- 生产部署优先同源访问前端与 `/api`，减少跨域凭据配置；不得开启任意来源的凭据式 CORS。
- Refresh Token 必须支持轮换。服务端仅保存其不可逆摘要及会话元数据，不在普通业务记录中明文保存。刷新成功后旧 Refresh Token 立即失效并签发新令牌；检测到已轮换令牌再次使用时，撤销对应会话族并要求重新登录。
- 退出登录时撤销当前 Refresh Token 会话并清除相关 Cookie。已签发的 Access Token 在过期前可能仍有效；如需即时失效，应通过短有效期与必要的会话状态校验实现，不得声称仅清 Cookie 就即时撤销所有已复制令牌。
- 对改变状态的请求校验 `Origin`/`Referer` 与预期站点，并结合 SameSite Cookie 防范 CSRF；Refresh Token 刷新与退出接口同样需要防 CSRF。
- JWT 签名密钥由环境变量或密钥管理设施注入；生产密钥缺失或仍为示例值时拒绝启动。用户令牌签名密钥与 Go/Python 内部服务凭据必须分离。

如果实际部署不能保证前后端同源或 Cookie 方案受环境限制，应先调整部署拓扑，不得静默改为将 Refresh Token 放进 `localStorage`。

## 三、授权与用户隔离

### 3.1 统一规则

- 用户 ID 只从已验证的会话身份中获取。
- 查询任务、线程、消息、报告和输入时，SQL 条件必须包含当前用户归属约束；不能先按资源 ID 查询后忘记校验归属。
- 对不存在和不属于当前用户的资源，外部 API 统一返回 `TASK_NOT_FOUND` 或对应资源的同类错误，不暴露其他用户资源是否存在。
- 内部 Python 回调采用服务间鉴权，并校验 `task_id`、`attempt_no`、`event_id` 与当前尝试；不得接受浏览器直接提交的分析结果作为可信报告。
- 管理运维权限不在 MVP 暴露为普通用户可调用的业务 API。

### 3.2 对话绑定

- 接受追问时，由 Go 绑定具体任务和当时有效的报告；Python 只收到这份绑定的报告、证据和允许的对话上下文。
- 重新分析只额外接收当前请求的 `user_note` 和来源报告；它们是待核查材料，不是已验证事实。
- 禁止跨用户、跨任务自动加载历史消息、报告或 Agent Memory。
- RAG 检索必须限制在系统允许的知识范围，并保留知识文档/片段的来源标识；不能将知识检索结果伪装成当前 Diff 的直接证据。
- Agent Memory 仅能读取当前用户有权访问且状态有效的记忆；写入、确认、拒绝、删除和引用均须保留可追溯标识。用户记忆不能跨账号共享，也不能自动加载无关历史对话。

## 四、Diff 输入和文件处理

### 4.1 MVP 默认限额

以下是首版开发/演示环境的保守默认值，均由服务端配置控制，用户不能通过请求提高上限：

| 项目 | 默认上限 | 超限处理 |
|---|---:|---|
| Diff 原始内容 | 1 MiB | 创建任务前拒绝，`INPUT_TOO_LARGE` |
| 变更文件数 | 500 | 创建任务前拒绝，`INPUT_TOO_LARGE` |
| 新增与删除行数合计 | 20,000 行 | 创建任务前拒绝，`INPUT_TOO_LARGE` |
| 文件路径长度 | 1,024 字符 | 拒绝该输入 |
| 单次 Diff 解析时限 | 5 秒 | 停止解析并返回明确失败/限制，不继续无限消耗资源 |
| 报告证据数量 | 200 条 | 结构化输出超限则修正一次；仍超限则拒绝结果或按契约失败 |

这些值是待通过真实样例校准的工程默认值，不是系统容量实测结论。若合法案例因限额被拒绝，再依据评测集调整，并同步更新配置说明与测试。

### 4.2 文件上传规则

- 仅接受明确的 Diff 文本文件；不解压压缩包，不接收仓库快照、二进制可执行文件或任意目录路径。
- 以服务端读取到的字节数为准，不信任客户端 `Content-Length` 或文件名后缀。
- 上传文件使用随机临时名，放在应用专用临时目录；不使用用户提供的文件名作为路径。
- 限制并发上传、请求体大小和解析耗时；解析结束后按清理策略删除临时文件。
- 路径规范化并拒绝路径穿越；不得按 Diff 中的路径读取宿主机文件。
- 对非法编码、二进制内容、异常超长行和畸形 Diff 进行安全失败处理，不将其送入无限修复循环。

## 五、外部模型与 Prompt Injection

- 用户提交前必须明确说明：Diff、为分析所需的代码片段以及用户明确提供的补充说明会发送给配置的外部模型供应商；取得确认后才能创建任务。
- Go 保存确认事实、时间、告知文本版本及关联用户/任务，并写入审计记录。线程后续追问和重新分析沿用该确认记录，但不得因此将无关任务内容发送给模型。若数据处理目的、供应商或外发范围发生实质变化，必须重新取得确认。
- 平台服务端统一持有模型 API Key；MVP 不接收、不持久化用户自带 Key。Key 通过环境变量或部署密钥设施注入，前端不得接触。
- 将 Diff、文件名、注释和历史报告视为不可信数据，不作为系统提示词或工具授权指令。
- Agent 只可调用白名单内的内部分析函数；不开放任意 Shell、任意 URL、任意 MCP 工具、数据库写操作或内网探测。
- 不执行用户提交代码，不运行构建脚本、测试脚本或安装依赖；静态分析工具如后续加入，也必须限定可执行文件、参数、时间、内存和文件系统权限。
- 供应商请求中仅发送完成当前分析所必需的数据；不得发送访问令牌、模型 Key、其他用户数据或无关对话。

## 六、日志、审计与可观测性

### 6.1 普通应用日志禁止项

不得记录：

- 原始 Diff、完整代码片段或完整用户对话正文；
- 密码、JWT、Cookie、模型 API Key、内部服务密钥；
- 其他用户的资源内容；
- 可复原敏感输入的完整模型请求体。

允许记录最小诊断字段：`request_id`、`task_id`、`attempt_no`、`event_id`、错误码、节点名、耗时、模型供应商/模型标识、Token 用量（若供应商提供）和经过脱敏的错误摘要。异常堆栈仅写入受控日志，且需经过脱敏。

### 6.2 审计事件

至少审计：账号注册/登录失败（限频汇总也可）、外部模型使用确认、任务创建、手动重试、重新分析、报告回调被接受/拒绝、资源删除或管理性操作。审计事件记录操作者、动作、目标资源 ID、时间、结果和必要的请求关联 ID，不记录原始 Diff 或密钥。

## 七、数据保留与删除

首版采用明确、可配置的默认保留期限，并实现定时清理或可重复执行的清理命令：

| 数据 | 默认保留期 | 说明 |
|---|---:|---|
| 原始 Diff 与上传临时文件 | 30 天 | 临时文件尽可能在分析完成后立即删除；原始输入到期后清理；删除后重新分析需用户重新提交 Diff |
| 报告、证据与任务元数据 | 90 天 | 证据仅保存必要事实、位置和解释，不复制整份 Diff |
| 对话消息 | 90 天 | 不进入普通日志；清理时与对应线程/任务关系一致 |
| Agent Memory | 按记忆类型设置独立期限；默认随来源数据到期或被删除时失效 | 仅保存被业务规则允许的摘要/事实；记录来源、用户归属、状态和删除关联，不把完整历史对话默认转成长期记忆 |
| RAG 知识文档与向量切片 | 由知识来源授权和配置决定 | 保存来源、版本、片段标识和向量模型版本；删除/停用知识源时同步处理切片与向量记录 |
| 安全与审计日志 | 180 天 | 保留必要的操作事实，不保留原始输入内容 |
| Outbox、消费去重与执行诊断记录 | 按恢复和排障需要设置独立清理规则 | 未发布、未确认或仍可能用于幂等判定的记录不得提前清理 |

保留期到期后的清理应可重入、分批执行并记录清理结果。删除报告时必须同步处理证据和对话关联；删除输入不应导致报告声称仍能读取完整原始 Diff。备份的实际删除延迟应在部署说明中披露。

MVP 暂不提供自助删除账号 UI；必须提供可执行的运维删除流程，并在账号删除时删除该用户的任务输入、报告、证据、对话及可删除的关联记录。为保留安全审计的完整性，可将必要审计主体匿名化，不保留不必要的个人资料。账号删除流程应有测试。

## 八、内部服务鉴权与密钥管理

- Go 到 Python 的任务分发/回调使用独立服务凭据或部署网络内的强鉴权机制；不能只因服务位于 Docker 网络就视为可信。
- 内部回调需绑定 `task_id`、`attempt_no`、`event_id` 和预期状态；对话回复还需绑定 `thread_id` 与对应事件。过期、重复或跨用户引用均应拒绝，且不得覆盖已生效报告。
- 服务密钥不得与用户 JWT 签名密钥复用。
- 密钥不得写入仓库、镜像层、Compose 默认值或示例配置；提交 `.env.example` 时只能放占位符。
- 生产配置与本地开发配置分离；开发默认密钥只能在本地使用，并在启动日志中明确环境，不输出密钥值。
- 回调需校验来源身份、当前任务状态、尝试次数和事件 ID；重复或过期回调必须幂等拒绝，不能覆盖报告。

## 九、依赖、部署与运行安全

- PostgreSQL、Kafka、Redis 不直接暴露公网；只开放必要的应用入口。
- 数据库账号遵循最小权限；Python Agent 不持有业务数据库写权限。
- Docker 容器尽量使用非 root 用户、固定依赖版本和健康检查；生产部署不挂载宿主机 Docker Socket。
- 禁止将上传目录作为静态可执行目录；容器文件系统尽可能只读，临时目录单独限制容量。
- 设置 HTTP 请求体、并发、模型请求、队列积压与执行时间上限，避免资源耗尽。
- 生产环境必须使用 HTTPS；CORS、Cookie、密钥、日志级别和模型端点不得沿用开发默认值。

## 十、MVP 安全验收清单

- [ ] 未登录请求不能访问用户资源。
- [ ] 用户 A 不能读取、追问、重试、重新分析或访问用户 B 的任务、线程、报告和消息。
- [ ] RAG 知识来源可追溯；Agent Memory 按用户隔离，删除/失效规则有效，不能跨用户召回。
- [ ] 密码只以成熟密码哈希形式存储；日志中无密码和令牌。
- [ ] Access Token 与 Refresh Token 有独立有效期；Refresh Token 轮换、重复使用检测、会话撤销和退出登录均有自动化测试。
- [ ] 生产配置缺失必需密钥时启动失败，不回退到示例密钥。
- [ ] 未确认外部模型使用时，不能创建分析任务。
- [ ] 请求体、文件大小、文件数、变更行数和解析耗时均有服务端限制。
- [ ] 文件名和 Diff 路径不能导致路径穿越或读取宿主机文件。
- [ ] Agent 不执行 Diff 中的命令或提示词指令，不具备任意网络访问能力。
- [ ] 普通日志不含原始 Diff、完整对话、密码、Cookie、JWT 或模型 Key。
- [ ] Go 与 Python 的内部回调经过鉴权，并能拒绝过期/重复结果。
- [ ] 数据保留清理可重复执行，且不会提前删除仍需用于恢复/幂等的记录。
- [ ] 账号删除运维流程能删除用户业务数据并妥善处理审计记录。

## 十一、明确不在 MVP 内

组织/团队 RBAC、SSO、MFA、第三方 OAuth、用户自带模型 Key、仓库/PR 集成、执行代码沙箱、完整 DLP、企业级密钥管理平台、复杂的账号自助找回与恢复流程不纳入 MVP。若部署对象或真实数据敏感度发生变化，应在扩大使用范围前重新评估。

## 十二、V1.2 修订记录

- 将认证方案统一为 Access Token + Refresh Token，与项目当前认证需求一致；明确 Cookie、轮换、重放检测、撤销与 CSRF 约束。
- 补充 RAG 知识来源追溯、Agent Memory 用户隔离、生命周期与删除关联规则。
- 加强外部模型确认记录与内部回调的归属/幂等校验要求。
- 其余输入限额、日志禁项、默认保留期限和部署边界沿用原稿；上线前仍需结合测试与部署条件核验。
