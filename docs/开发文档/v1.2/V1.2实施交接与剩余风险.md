# CodeRisk V1.2 实施交接与剩余风险

**状态：** 设计决策已统一，下一步进入代码仓库盘点与分阶段实现；不代表任何功能已实现或测试通过。

## 本次已统一

1. MVP 支持用户取消尚未进入终态的任务。Go 在 PostgreSQL 事务内执行条件状态转换并写 Outbox；取消后的迟到完成/失败回调不得覆盖 `CANCELLED`。
2. 取消 API：`POST /api/v1/analysis-tasks/{task_id}/cancel`；取消事件：`analysis.cancel_requested`。取消只承诺尽力停止后续执行，不承诺模型请求可即时中断。
3. PostgreSQL + pgvector 为 MVP 默认向量存储，BGE-M3 为首选 Embedding。质量、性能和资源消耗待实测。
4. 保留 Go + PostgreSQL 作为业务状态权威，Kafka + Outbox 负责跨服务事件，Celery + Redis 负责 Python 内部调度。

## 必须用测试证明的行为

- 两个并发请求中取消与完成只允许一个终态事务成功。
- 取消后重复/迟到的成功或失败回调不能覆盖 `CANCELLED`。
- 同一取消请求重放不会创建额外尝试或重复业务结果。
- 同一幂等键不同请求内容返回冲突。
- Kafka 重投、Celery 重启和 Outbox 重发不增加 `attempt_no`。
- 用户 A 无法访问用户 B 的任务、报告、知识或记忆。
- 未执行测试必须标记“未运行”，不能写成通过。
