## 二、最终冻结的关键基线

- 任务状态固定为 `PENDING`、`QUEUED`、`RUNNING`、`SUCCEEDED`、`PARTIAL_SUCCESS`、`FAILED`。
- 每个任务最多 4 次业务执行；只有 Go 在创建首个执行或接受合规手动重试时分配 `attempt_no`。
- 默认期限：模型单次请求 30 秒，发布/排队等待 120 秒，执行 180 秒，恢复判定窗口 60 秒。
- 基础设施重投最多 3 次，约 1/2/4 秒指数退避并加随机抖动，不增加业务尝试。
- Diff 默认限制：1 MiB、最多 500 个变更文件、增删行合计 20,000 行、解析 5 秒。
- 默认保留：Diff 30 天；报告、证据、任务元数据、对话 90 天；审计日志 180 天。
- Risk / Hardness 枚举、证据结构、核心成功条件以 Agent 工作流规范为准。
- Go + PostgreSQL 维护业务事实；Python 只做分析并经鉴权回调，不直接写业务数据库。

## 三、仍需在实现阶段验证（不是设计悬案）

1. 用真实环境验证默认超时与恢复窗口是否适合模型延迟和容器重启时长。
2. 生成数据库迁移、API schema、Kafka event schema 与 Python 模型，并做契约测试。
3. 执行用户隔离、并发重试、重复事件、重复/迟到回调、Celery 重启、Outbox 恢复和数据清理测试。
4. 建立固定 Diff 评测集，记录证据有效率、风险命中/误报、Hardness 一致性、延迟和成本。
5. 核验实际代码与文档一致；当前没有证据表明业务代码或测试已完成。
